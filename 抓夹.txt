那就可以确定了：你现在已经不是接口问题，而是**Gazebo 当前直接 position 控制不会产生可用的 joint effort**。

这一步不要再动 launch、红球、controller_manager、YAML。只改一个文件最合适：

```text

```

我已经给你做了一个**最小修改版 v5**：

[下载 dummy_ws_effort_pid_v5.zip](sandbox:/mnt/data/dummy_ws_effort_pid_v5.zip)

包里核心只有这个文件：

[下载修改后的 dummy-ros2.xacro](sandbox:/mnt/data/dummy_ws_effort_pid_v5/dummy_ws/src/dummy-ros2_description/urdf/dummy-ros2.xacro)

这版和你当前恢复正常的 v4 相比，只做了一件事：给 Joint1～Joint6 加 position PID 参数。

关键是，**外部 command interface 仍然保持 `position`**，所以你的：

```text
/arm_controller/follow_joint_trajectory
```

完全不用改，MATLAB 位置轨迹发送方式也不用改。

官方 `gazebo_ros2_control` 的 Humble 文档明确支持在 position command interface 下通过 PID 参数启用位置 PID；插件检测到 `pos_kp/pos_ki/pos_kd` 后，会把位置误差转换为力矩并通过 Gazebo `SetForce()` 施加到关节。这样 `/joint_states.effort` 才会有实际值。([控制ROS][1])

我给你的初始参数是：

```text
Joint1: Kp=60   Ki=0   Kd=3
Joint2: Kp=90   Ki=0   Kd=5
Joint3: Kp=75   Ki=0   Kd=4
Joint4: Kp=45   Ki=0   Kd=2.5
Joint5: Kp=30   Ki=0   Kd=1.8
Joint6: Kp=20   Ki=0   Kd=1.2
```

我先把积分项设为 0，是为了避免一上来积分累积导致振荡或饱和。后面如果出现静态误差，再小幅增加 Ki。

```bash
  joint_names: [Joint1, Joint2, Joint3, Joint4, Joint5, Joint6],
  points: [{

```

这次看 `/joint_states` 中：

```text

```

如果变成类似：

```text
effort:
- 0.18
- -0.74
- 0.51
- 0.12
- -0.08
- 0.03
```

并且随运动变化，就说明：

```text
position reference
      ↓
Gazebo position PID
      ↓
joint torque
      ↓
Gazebo dynamics
      ↓
/joint_states.effort
```

还有一点需要注意：Action feedback 里的：


仍然可能为空，这不影响我们。论文和 MATLAB 后面用的是 `/joint_states.effort`，不是 FollowJointTrajectory feedback 里的 effort。
